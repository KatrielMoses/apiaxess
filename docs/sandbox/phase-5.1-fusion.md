# APIaxess Phase 5.1: Static/Dynamic Fusion

Phase 5.1 is the pure-compute merge pass over the canonical API model. Static
and dynamic extraction remain evidence producers; `apiaxess-fusion` reconciles
their provenance-tagged candidates without capture, network access, or a final
confidence calculation.

## Merge contract

Fusion uses the existing endpoint identity: normalized method plus path
template. Static identities remain primary, and dynamic-only identities are
retained rather than treated as a correction to static coverage.

Every fact keeps all of its candidates and evidence. Fusion appends a
`MergeRecord` for each source comparison:

- `gap_fill` means one source was silent. Silence never creates an absence
  candidate or weakens the assertion from the other source.
- `refinement` means dynamic evidence narrows or sharpens a static assertion.
  Schema refinements use a derived fusion candidate containing a union/widened
  shape when samples demonstrate multiple types.
- `true_conflict` means both sources assert incompatible values. Both values
  remain available with their original provenance; the relation is state in
  the model, not a failure diagnostic.
- `agreement` records the useful case where both sources support the same
  candidate.

Resolution is field-class-specific. Authentication selects dynamic-supported
evidence when available, schema shapes widen across candidates, and presence
retains static completeness while recording dynamic confirmation. There is no
global dynamic-wins or last-writer-wins rule. The selected candidate and the
policy remain in `Resolution`, while losing candidates and merge history stay
auditable.

Widened candidates are backed by `DerivedFact` provenance entities generated by
the fusion activity. Their `derived_from` links preserve every contributing
static and dynamic evidence entity, so Phase 5.2 can recompute confidence from
the same evidence graph.

## Diagnostics and verification

The pass rejects duplicate endpoint identities, unusable provenance, invalid
input models, and invalid post-fusion results with structured diagnostics. An
expected true conflict is not itself diagnostic noise.

The fixture suite proves partial dynamic coverage, gap-fill without negation,
dynamic authentication selection, retained true conflicts, schema widening,
fusion provenance, and durable JSON round-tripping.
